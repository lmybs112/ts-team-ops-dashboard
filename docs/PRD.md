## 1. 目標、使用者與成功標準

### 1.1 產品目標

讓 mei（與 CTO bot）能在 **單一畫面** 完成「發現阻塞 → 篩選 → 打開詳情 → 更新狀態／指派」的 **整頁任務路徑**，並一眼掌握哪個專案、哪位 Agent、哪些 Issue 卡住。

產品定位：**兩個可切換的整頁視圖**——**View Office**（整頁貓虛擬辦公室）與 **View Linear**（整頁 Linear 式 Issues／Projects）。好用度對標 Linear；辦公室是獨立視圖，**不是**塞在三欄中間的裝飾。成功看切換清楚、資料／篩選同源、任務路徑完整。

### 1.2 目標使用者

| 角色 | 使用情境 |
|------|----------|
| **mei**（主要） | 指揮窗口擁有者；掃讀專案與 bot 進度、介入阻塞、改優先級 |
| **CTO bot**（主要） | 拆解／指派／追蹤；與 mei 同權改全部任務 |
| **各職缺 bot**（次要） | 更新自己任務狀態；透過 ingest 回報 |
| **產品經理 bot** | 對齊需求與任務狀態（辦公室內一員） |

### 1.3 核心問題

進度散落在 GitHub、各 bot 對話與口頭回報 → 無法 3 秒內回答「誰卡在哪」。mei 要求主體驗是 **空間化角色儀表板**（辦公室裡的貓＝職缺），不是後台表格。

### 1.4 成功標準（Must）

> **v1.3 糾偏（mei）**：要的是 **Office 與 Linear 兩個可切換視圖／頁面**，**不是**「一頁三欄合體（左專案｜中辦公室｜右 Inbox）當唯一總覽」。合體三欄 ≠ mei 原意。

> **糾偏（mei／CTO）**：成功標準衡量的是 **整頁任務完成路徑與互動品質**，不是「中央有沒有換成貓辦公室場景」。貓辦公室是總覽整合層；若路徑慢、重整、丟總覽、篩選不同源——即使場景再精美也 **不算過關**。

| ID | 標準 |
|----|------|
| S1 | **雙視圖可達**：可進入 View Office（整頁貓辦公室）與 View Linear（整頁 Issues／Projects）；切換控制清楚可見 |
| S2 | **完成路徑 A（掃阻塞）**：≤ 3 秒指出「哪個 Project／哪個 Agent／哪條 Issue blocked」並能點進詳情 |
| S3 | **完成路徑 B（篩選）**：在當前視圖用 Project／Agent／Status 或 ⌘K 篩選 → **同源過濾**；**零整頁重整**；切 Office⇄Linear 後篩選仍在 |
| S4 | **完成路徑 C（改狀態）**：在 Office 點貓或在 Linear 點 Issue → 開詳情 → 改 Status／填 blockedReason → 存檔；不丟該視圖上下文；聚合狀態同步 |
| S5 | **完成路徑 D（切 Agent）**：Office dock／點貓或 Linear 指派篩選快切 Agent；詳情／列表選中態一致 |
| S6 | **互動品質**：點擊可靠（含走動時）；側欄開／關穩；無誤觸導致丟上下文；關鍵操作有即時回饋 |
| S7 | **設計準則（硬性）**：滿足原文 10 條；黑白灰＋狀態色；無浮誇光效；貓＝識別；整體像可管理 AI 員工的 SaaS |
| S8 | **View Office**：整頁貓虛擬辦公室可掃 Agent 狀態／阻塞；點貓開詳情；**不是**三欄合體的中欄裝飾 |
| S9 | **View Linear**：整頁 Issues／Projects 達 Linear 級操作（列表、篩選、詳情、快篩零重整）；詳情不丟列表上下文 |
| S10 | **交件**：可點 prototype（公開 https 由 CTO 佈）；手機仍須能完成「專案掃讀 → 下鑽改狀態」路徑 |
| S11 | **視圖切換＋同源**：Office⇄Linear（及 Project／Settings）切換清楚；Filter State 跨視圖保留；**禁止**把「一頁三欄合體」當唯一總覽 |

## 產品架構定案（v1.3｜Office ∥ Linear 雙視圖）

> **mei 原意（強制）**：貓辦公室與 Linear **是兩個可切換的視圖／頁面**，不是一頁三欄合體。  
> **防誤解**：`左專案｜中辦公室｜右 Inbox` 合體三欄 **≠** mei 要的。該敘述在 v1.2.x 出現過，**v1.3 起刪除／降級**，不得再當唯一總覽。

### A. 資料模型（對齊 Linear 思維｜不變）

| 實體 | Linear 類比 | 本產品定義 |
|------|-------------|------------|
| **Project** | Project | 6 專案＋「全部」；清單見 §2.2 |
| **Issue** | Issue | 任務單元；含 title、project、assignee Agent、status、blockedReason |
| **Agent** | Assignee／成員 | 7 職缺 bot；在 Office 視圖視覺＝一隻貓／工位 |
| **Status** | Workflow state | 固定四態：`todo`／`doing`／`blocked`／`done` |

規則：

- **單一資料源**：Office、Linear、Project 頁、看板、矩陣、dock、⌘K **全部讀寫同一套 Project／Issue／Agent／Status**
- Issue 必屬一個 Project、一個 Agent、一個 Status
- Agent 主狀態＝其 Issues 聚合（blocked > doing > todo > done）
- 權限、ingest、非 GitHub 同步仍依 §6

### B. 雙主視圖（桌面｜定稿）

| 視圖 ID | 名稱 | 形態 | 用途 |
|---------|------|------|------|
| **`view-office`** | **View Office** | **整頁**貓虛擬辦公室 | 空間掃讀 7 Agent；點貓看狀態／任務；動畫＋走動 |
| **`view-linear`** | **View Linear** | **整頁** Linear 式工作台 | Issues 列表為主；Projects 導覽／專案下鑽；Inbox／詳情面板 |

硬性：

1. 兩個視圖都是 **整頁**（full-page），不是同一頁裡的左右中三欄拼盤
2. 必須有 **清楚的切換控制**（頂部 segmented control／toggle／導航項，文案如 `Office`｜`Linear`）
3. 切換時 **Filter State 同源保留**（見 §N.3）
4. 預設落地：MVP 可預設 `view-office` 或記住上次視圖；**兩者都必須一鍵可達**
5. View Linear **內部** 可有左專案列表＋主列表＋右詳情（這是 Linear 頁自己的布局，**不是**「辦公室塞在中間」）
6. View Office **內部** 可有輕量 HUD（狀態圖例、篩選 chip、點貓後抽屜），但主體必須是整頁辦公室，**禁止**再規定「中欄辦公室＋左欄＋右欄」為唯一總覽結構

### C. 同源與次頁

| 表面 | 關係 |
|------|------|
| View Office | 空間化 Agent 總覽 |
| View Linear | Issues／Projects 作業台 |
| Project 頁 | Linear 體系下的專案下鑽（可自 Linear 進入） |
| Settings | 簡版設定 |
| Board／Matrix | P1；同 Issue 資料；可自 Linear 進入 |

### D. 好用度對標（可驗證｜任務路徑優先）

| ID | 對標項 | 驗收 |
|----|--------|------|
| U1 | 雙視圖切換 | ≤ 1 次點擊切 Office⇄Linear；控制項永遠可見 |
| U2 | 一頁掃阻塞（Office） | 在 Office 整頁可不切視圖看出哪些 Agent blocked |
| U3 | 一頁掃阻塞（Linear） | 在 Linear 整頁可用列表／篩選掃完 blocked Issues |
| U4 | 快篩零整頁重整 | 任一視圖內篩選不 full reload；切視圖不丟 Filter State |
| U5 | 詳情不丟上下文 | Office 點貓抽屜／Linear 右詳情均不導致「只剩詳情、丟列表或辦公室」 |
| U6 | 操作同源 | 篩選、⌘K、點貓、列表點選 → 選中態與資料一致 |

### E. 防誤解（v1.3｜必讀）

| 錯誤理解 | 正確理解 |

## 視圖與頁面導航（v1.3｜mei 定案）

> 產品要能在 **View Office** 與 **View Linear** 之間切換；另有 Project／Settings 等頁。跨視圖篩選同源。

### N.1 導航地圖（桌面）

| 路由／視圖 | 優先級 | 形態 | 用途 |
|------------|--------|------|------|
| **`view-office`** | P0 | **整頁** | 貓虛擬辦公室 |
| **`view-linear`** | P0 | **整頁** | Linear 式 Issues（主）＋ Projects 導覽 |
| **Project** | P0 | 頁 | 單一 Project 詳情（自 Linear 或 ⌘K 進入） |
| **Board** | P1 | 頁／視圖 | 四態泳道 |
| **Matrix** | P1 | 頁／視圖 | Project × Agent |
| **Settings** | P0 簡版 | 頁 | 角色切換、版本 |

**切換控制（Must）**：

- 頂部固定控制：`Office`｜`Linear`（或等效），任何子頁都能看到／回到這兩個主視圖
- 切換＝換視圖／路由，不是只改中央 widget
- URL 建議：`/office`、`/linear`、`/projects/:id`、`/settings`

### N.2 各視圖必備

#### View Office（整頁）
- 全畫布辦公室＋7 貓工位；狀態標籤；點貓開詳情抽屜／面板
- 可有頂部篩選 chip／阻塞摘要／圖例；**不要**再規定左中右三欄合體
- 底 dock 可保留為 Agent 快切（屬 Office HUD）

#### View Linear（整頁）
- 對標 Linear：Issues 主列表＋篩選／排序＋詳情側欄
- Projects 導覽（側欄或頂部）可進 Project 頁
- **不含** 把 3D 辦公室嵌在中欄

#### Project／Settings／Board／Matrix
- 同 v1.2.2 內容要求；Board／Matrix 掛在 Linear 體系下為 P1

### N.3 跨視圖篩選規則（硬性）

全域 Filter State：`projectId`、`agentId`、`status`、`query`（預設皆 all／空）。

1. Office⇄Linear⇄Project⇄Board **讀同一 Filter State**
2. 切視圖 **不重置** 篩選（除非「清除篩選」）
3. 進入 Project 頁 → 寫入該 `projectId`；返回保留
4. Office 點貓 → 設 `agentId` 並開詳情；切到 Linear 時列表已篩該 Agent
5. ⌘K 可跳 Office／Linear／Project／Issue
6. 建議 URL 同步 Filter（P0 建議）

### N.4 手機
- 預設偏專案／Issue 列表（Linear 向）
- Office 可為次要入口或簡化場景
- Filter State 規則相同

### N.5 與成功標準
- 切換控制失敗＝產品不合格
- 仍須滿足任務路徑（掃阻塞→篩選→改狀態）

### 4.2 硬性設計準則（與上章「設計準則（硬性）」同義；表格版）

產品整體必須像 **真的可以拿來管理 AI 員工的成熟 SaaS**，參考氣質：

| D1 | **禁浮誇** | **不用**浮誇的 AI 光效、霓虹、過度漸層、科技感粒子／掃描線／全息特效 |
| D2 | **一貓一 Agent** | 每隻貓＝一個 AI Agent＝一個獨立工位 |
| D3 | **工位有內容** | 每個工位可見：螢幕、文件／資料、狀態、任務（至少狀態＋當前任務標題可讀） |
| D4 | **成熟 SaaS UI** | 產品殼（頂欄／左欄／右欄／底欄）走 Linear／Notion／Slack／Raycast 路線：對齊、間距、字重、邊框克制 |
| D5 | **貓＝識別，不賣萌** | 貓咪是角色識別符號；**禁止**整畫面賣萌、貼圖堆疊、表情包化主導 |
| D6 | **色盤** | **黑、白、灰**為主＋**少量狀態色**（僅用於四態／badge）；大面積不用高飽和裝飾色 |
| D7 | **可點進工位** | 點工位／貓 → 看該 Agent **正在做什麼**（執行狀態＋任務） |
| D8 | **底部快切 Agent** | 底部 dock／列可快速切換 7 個 Agent（必做，非可選） |
| D9 | **右側＝今日任務／執行狀態** | 右側面板預設或選中 Agent 時顯示：**今日任務**與**執行狀態**（見 §7） |

**一句話**：管理台第一、場景第二、角色識別第三；可愛不能壓過可操作性。

### 4.3 視覺質感與材質

- 中央場景可為 **3D／半寫實辦公室**（對齊 mei 參考圖＋素材板），但 **UI 殼必須克制**（D1／D4／D6）
- **禁止** 以 2D Kenney 像素地圖／像素貓 **作為最終交付視覺**
- 場景可有輕微景深／玻璃工位，但不得變成光效秀
- 狀態色（少量使用）：

| 狀態 | 色 |
|------|-----|
| todo 待處理 | `#6B7280` |
| doing 進行中 | `#2563EB` |
| blocked 阻塞 | `#DC2626`（最醒目） |
| done 完成 | `#16A34A` |

### 4.4 桌面資訊架構（定稿｜對齊 v1.3 雙視圖）

詳見 **「產品架構定案（v1.3）」**。摘要：

1. **頂欄**：產品名＋阻塞摘要＋**Office｜Linear 切換**＋⌘K＋次要入口（Board／Matrix／Settings）
2. **View Office**：整頁辦公室畫布＋點貓詳情＋可選 dock

## 6. 任務狀態、權限與資料

### 6.1 四態（固定，不可自訂）

| status | 中文 | 定義 |
|--------|------|------|
| `todo` | 待處理 | 已建立、尚未開始 |
| `doing` | 進行中 | 正在執行 |
| `blocked` | 阻塞 | 無法前進；**必須** `blockedReason`（≤ 120 字） |
| `done` | 完成 | 已交付／驗收通過 |

- 一任務同時僅一狀態
- 變更記錄 `updatedAt`（顯示 Asia/Taipei）、`updatedBy`

### 6.2 貓的「主狀態」聚合（地圖標籤）

對該 `roleId` 下所有任務（若有專案篩選則僅該專案）：

1. 任一 `blocked` → 主狀態 **blocked**（取最近更新的 blockedReason 摘要 ≤ 40 字）
2. else 任一 `doing` → **doing**
3. else 任一 `todo` → **todo**
4. else → **done**（無任務可視為空閒／done，文案由設計定）

### 6.3 權限（定稿）

| 操作者 | 權限 |
|--------|------|
| **mei**、**CTO** | 可建立／編輯／改狀態／改指派 **全部** 任務 |
| **各職缺 bot** | **僅** 可改 `assigneeRole`＝自己的任務（含填 blocked 原因） |
| 未授權 | 拒絕寫入 |

MVP 認證可簡化（內網／簡單 token／原型假登入）；行為規則仍須可測。

### 6.4 資料來源（MVP）

| 來源 | MVP | 說明 |
|------|-----|------|
| 手動 UI | ✓ | 側欄／表單 |
| Bot **ingest API** | ✓ | 結構化 JSON，事件驅動 |
| GitHub Issues／PR 同步 | ✗ | **Phase 1.1**，本 PRD 不做 |

#### Ingest 契約（後端）

```json
{
  "projectSlug": "marketing",
  "assigneeRole": "frontend",
  "title": "完成商品卡 hover 狀態",
  "status": "done",
  "source": "bot_report",
  "sourceRef": "agent:frontend:task-123",
  "blockedReason": null
}
```

- 冪等鍵：`source` + `sourceRef`
- `status=blocked` 且缺／空 `blockedReason` → **400**，不寫入
- 非法 `assigneeRole`／`projectSlug` → **400**

### 6.5 任務欄位（最小集）

| 欄位 | 必填 | 說明 |
|------|------|------|
| `id` | ✓ | 系統產生 |
| `title` | ✓ | 短標題 |
| `projectSlug` | ✓ | 六專案之一 |
| `assigneeRole` | ✓ | 七職缺之一 |
| `status` | ✓ | 四態 |
| `blockedReason` | 條件 | blocked 必填 |
| `source` | ✓ | `manual` \| `bot_report`（`github` 保留 enum，MVP 不寫入） |
| `sourceRef` | | 可空 |
| `updatedAt` | ✓ | ISO |
| `updatedBy` | ✓ | 操作者識別 |

## 7. 點工位／Agent → 右側面板（今日任務／執行狀態）

### 7.1 開啟方式

- 點辦公室內的工位／貓／標籤
- 點 **底部 dock** 對應 Agent（必做快切）
- Esc／×／關閉鈕關閉或取消選中

### 7.2 右側面板內容（Must）

面板定位：**該 Agent 正在做什麼** — 今日任務＋執行狀態（非裝飾卡）。

必含：

- Agent／職缺名、主狀態 chip
- **執行狀態**摘要（主狀態＋若 blocked 則原因全文）
- **今日任務**列表（尊重當前專案篩選；至少顯示進行中／阻塞優先）
- 每列：title、專案、狀態、blockedReason（若有）、updatedAt
- mei／CTO：新建任務、改狀態、改指派、編輯標題
- 該 bot：僅改自己任務狀態（含 blocked 原因）
- blocked 無原因 → 阻擋儲存並提示

未選中任何 Agent 時：右側可顯示「選擇工位或底部 Agent」空態，或全局今日阻塞清單（設計二選一，須克制）。

### 7.3 與走動／動畫的關係

點擊熱區在貓移動時仍須可點；動畫不可擋住或吞掉 click（見 §9）。動畫須服務狀態可讀，**不可**變成賣萌表演。

## 8. 手機體驗（MVP 必做）

### 8.1 原則

- **手機首屏＝專案掃讀**（全部＋6 專案列表，狀態／blocked／doing 一眼可見）
- **辦公室 3D 地圖以桌面為主**；手機可簡化場景或縮為次要區塊，**不要求** 完整走動體驗
- 下鑽路徑：**專案 → 成員／任務 → 詳情 sheet（底部或全屏覆蓋）**

### 8.2 手機流程

1. 開啟 → 專案列表（掃 blocked）
2. 點專案 → 該專案相關成員列表或簡化辦公室區＋成員入口
3. 點成員 → sheet 顯示任務；可改狀態（權限內）
4. 返回／「全部」還原

### 8.3 RWD 斷點建議

- ≤ 430px：手機殼（專案優先）
- > 430px：桌面殼（左欄＋辦公室）

## 9. 動態：狀態動畫與走動（定案：兩者都要）

### 9.1 狀態動畫／姿勢（Must）

每態須有可辨視覺差異（對齊素材板表情／動作）：

| 狀態 | 最低要求 |
|------|----------|
| `todo` | 待機／閒置可辨 |
| `doing` | 工作向姿勢（例：打字／操作） |
| `blocked` | **最醒目**（例：煩躁／趴下＋紅色標） |
| `done` | 放鬆／完成可辨 |

狀態變更時應切換姿勢或播短動畫；手機可只保留狀態動畫、弱化走動。

### 9.2 辦公室內走動（Must，桌面）

- 貓可在合理路徑短距移動（工位 ↔ 走廊），**不要亂飛／穿牆**
- 迴圈輕量（CSS／sprite／短 loop 即可），勿卡頓
- **點擊開側欄不可因走動而失效**（熱區跟隨或足夠大的可點區域）

### 9.3 非目標（動態）

- 不做多人即時連線漫遊、語音、走近聊天（真 Gather 社交）
- 不做物理引擎級碰撞
